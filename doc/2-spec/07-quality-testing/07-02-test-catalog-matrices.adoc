== How to read the catalog

.Strategy question
****
What strategy lets anyone check, from a requirement, which tests prove it, and from a failing test, what is broken?
****

A catalog entry is a named group of tests about one subject: one test class, or a few.
Its identifier is the tag of those tests in the code and the name under which their result is reported; a failing build names catalog entries, not file paths.

.Columns
[%unbreakable, cols="3,12", options="header"]
|===
| Column | Content
| ID | `TU` unit, `TC` component, `TI` integration, `TE2E` end-to-end; then the context
| What it proves | The situation and the expected outcome, in one sentence. The complete cases are the cells, rules and scenarios it refers to.
| Family | Nominal, error, edge or invariant (document 07-01). An entry may cover several.
| Verifies | The rules, use cases, scenarios or requirements proven by the entry
|===

The catalog is written before the code and grows with it.
An entry may be split when its subject grows; its identifier is then kept by the part that keeps its meaning, as for every identifier of this specification.
